# 研发助手部署与运维

适用项目：IVD 研发物料工作台，schema migration v12。

## 服务组成

- `ivd-workbench`：Express API 与 React 静态前端；负责用户登录、组织资料、管理员配置、任务状态和审核确认。
- `ivd-ai-worker`：独立 Pi Agent Worker；消费 SQLite 持久队列，处理文档解析、报告结构化分析、问答和配方/配液建议。
- `ivd-literature-worker`：独立文献解析与向量索引 Worker。
- `ivd-report-knowledge-worker`：独立研发报告知识向量索引 Worker；按当前报告证据和复核值同步 Qdrant。
- `qdrant`：独立向量数据库；文献与报告知识使用不同集合，持久数据放在 `qdrant-data` 卷。
- Web/API 与三个 Worker 挂载同一 `ivd-data:/app/data` 卷，包含 `ivd.sqlite`、`attachments`、备份目录和报告向量缓存。SQLite 是单节点事务存储，Worker 与 API 不应使用各自独立的数据卷。

## Compose 启动

```powershell
Copy-Item .env.example .env
docker compose up --build -d
docker compose ps
```

Compose 等待 Web/API `/api/health` 健康后再启动 Worker。AI 与文献 Worker 的健康检查读取共享 SQLite 心跳；若 Web/API 与 Worker 未挂载同一数据卷，Worker 会被报告为不健康，任务也不会被正常消费。报告索引 Worker 使用配置的 `QDRANT_URL` 和 `QDRANT_API_KEY` 访问 Qdrant。

首次建立管理员：

```powershell
$env:ADMIN_NAME = '研发管理员'
$env:ADMIN_EMAIL = 'admin@organization.example'
$env:ADMIN_PASSWORD = '替换为至少12位的组织密码'
docker compose exec -e ADMIN_NAME -e ADMIN_EMAIL -e ADMIN_PASSWORD ivd-workbench npm run setup:admin
Remove-Item Env:ADMIN_NAME,Env:ADMIN_EMAIL,Env:ADMIN_PASSWORD
```

## Pi provider 设置

每项 AI 队列任务创建时固定记录累计 token 预算。单次输出上限限制单次 provider 响应；任务预算按 Pi provider 实际报告的 `totalTokens` 累计（input、output、cacheRead、cacheWrite），跨工具轮次与任务重试共享。Pi usage 分项缺失、总数不一致或请求中断未结算时保留已知计数并阻止后续模型请求。预算在每次请求前检查，输入用量须等待当前 provider 响应后才能得知，因此一个在途请求可能导致超过预算；不显示估算费用。

1. 管理员在部署进程环境或 `.env` 中提供 `IVD_AI_API_KEY`，然后重建/重启 Worker：

   ```powershell
   docker compose up -d --force-recreate ivd-ai-worker
   ```

2. 在系统“研发助手 → 模型设置”配置 provider、模型 ID 和 OpenAI 兼容服务地址（使用官方 provider 时不需要兼容地址）。页面不会接收、回显或持久化 API key。
3. 管理员可执行“测试连接”。任务状态需同时显示 provider 配置完整及 Worker 在线。
4. 未提供密钥或模型配置时，任务保留为“等待配置”；Worker 不调用外部模型，也不写入伪造的分析、回答或建议。

不要将真实密钥放入 README、Compose 源文件、截图、浏览器请求或 SQLite 配置记录。旋转密钥后重建 Worker，并在管理员界面确认连接。

## 任务与数据边界

- `ai_jobs`、`ai_job_events`、`ai_outbox_events` 及 `assistant_messages` 是持久队列和审计记录；Worker 重启后由租约过期/回队机制恢复任务。
- 当前默认文档解析支持 DOCX、XLSX、CSV、TSV、TXT；其他报告/仪器格式保留原始附件和文件哈希，标记为未解析或部分解析。公式不会执行；隐藏工作表和公式缓存可进入结构记录。
- 每条结构化观察和模型引用均保存报告版本、附件版本、内容 SHA-256 与定位。文件版本变化、软删除或来源变化会使旧引用失效；运行中的旧分析/建议不会发布。
- 会话仅限创建者和管理员读取；模型通过只读工具访问当前有效资料。所选报告或配方上下文会在服务端执行限制。
- AI 配方建议经服务端单位/量纲/物料校验后，显式确认只创建组织共享的草稿版本。AI 配液建议依据系统确定性配方计算和实时批次快照；确认前重新核对版本、证据、批次、有效期和数量。确认只创建 `planned` 任务，不自动发布配方、不扣库存。
- 保存正式业务记录前，API 将建议状态、期待版本、证据、库存指纹和幂等键在事务中再次核验。重复确认返回原结果，不重复创建记录。

## 备份与恢复

系统设置页面提供数据库与附件一体化 ZIP 备份，清单为每个文件记录 SHA-256。SQLite 中的报告索引任务和校验过的 Embedding 缓存纳入备份；Qdrant 点属于派生索引，不放入此 ZIP。恢复后启动 Worker 会核对当前报告指纹及 Qdrant 点，缺失点优先从本地缓存重建；缺少缓存时需要已配置 Embedding endpoint 与服务端密钥。恢复前停止 Web/API 与所有 Worker：

```powershell
docker compose stop ivd-ai-worker ivd-literature-worker ivd-report-knowledge-worker ivd-workbench
docker compose run --rm --no-deps ivd-workbench npm run restore:backup -- --file=/app/data/backups/备份文件.zip
docker compose up -d ivd-workbench ivd-ai-worker ivd-literature-worker ivd-report-knowledge-worker
```

恢复过程会在目标数据卷内暂存文件，校验数据库完整性、外键、路径、附件 SHA 和数据库关联；旧数据库及附件失败回滚由恢复安全目录保留。验收需确认 API 和 Worker 使用同一个命名卷，并检查报告/附件下载哈希、知识与任务记录、备份清单都与恢复前一致。Qdrant 可保留原派生点，报告知识 Worker 启动后依报告指纹检查；若 Qdrant 数据卷丢失，则用 SQLite 缓存离线重建已缓存向量。生产恢复操作必须先停掉 Web/API 和所有使用同一数据库卷的 Worker，不能让 SQLite 处于活动写入状态。

## 部署主机验收清单

当前开发环境未运行 Docker，以下部署验收需在目标主机实际执行并记录结果：

- `docker compose ps` 显示 Web/API 和 Worker 健康；Worker 最近心跳持续更新。
- Web/API 与 Worker 的 `DATA_DIR` 指向同一个 `ivd-data` 命名卷。
- 密钥配置时管理员连接测试通过；密钥为空时任务等待配置且无 provider 外呼。
- 生成一个隔离测试任务，确认 Worker 消费并写入可追溯来源；确认建议后，业务记录只发生一次。
- 在可丢弃的演练卷完成备份/恢复并比对附件 SHA；避免对正式业务卷做故障注入。
- 如启用 HTTPS profile，确认域名解析、防火墙 80/443、Caddy TLS 证书续期和 `COOKIE_SECURE=true`。
