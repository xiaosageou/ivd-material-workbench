## 2026-10-28 第三轮任务累计 token 预算

每个队列任务在创建时固定保存可配置预算。Pi 的 `totalTokens` 按 provider 报告的 input、output、cacheRead、cacheWrite 累计；reasoning 属于 output 子项，不重复计算。单次输出上限与任务累计预算分别配置、展示。跨工具调用与任务级重试读取同一任务用量状态；预算耗尽后在下一次请求前阻断，已发出请求的输入消耗只能在响应后得知，因此单个在途请求仍可能造成超预算并据实记账。

Usage 必须具有完整非负整数分项，且与 Pi `totalTokens` 一致才写入精确计数。字段缺失/不一致、请求中断或 Worker 租约过期而留有未结算请求时，将该请求标记为未知，保留此前已知总数并关闭重试入口；若错误终态仍提供完整一致 usage，照常累计。不会填造 0，也不展示价格或估算费用。持久记录累计预算、input/output/cache 计数、total、请求次数、未知次数、最后 response ID、provider stop reason 和任务停止原因。限流、凭据、输入、配额、网络超时等分类明确；可重试错误最多三次并按 2/4/8 秒指数退避（封顶 30 秒），用量未知时停止自动重试。

正式 AI contract smoke 覆盖多轮工具请求、cache read/write 计入预算、额度前后请求是否发出、在途输入超额、跨 attempt 预算继承、缺失/不一致 usage 失败关闭、未结算请求结算、取消、限流退避及最大尝试次数。schema v8 增量新增任务用量字段。构建、业务 smoke、AI smoke、AI contract、v1→v8 migration smoke 与隔离 Worker 心跳通过；本轮不重跑浏览器。当前交付状态：**等待主代理浏览器验收及最终复审**。

## 2026-10-28 第四轮 usage 缺失返修

Pi OpenAI-compatible stream adapter 会先将 assistant `Usage` 初始化为全零；provider 没有发 usage chunk 时，该默认对象仍随成功文本、工具调用或 HTTP 错误返回。预算控制器现把 `totalTokens === 0` 保守判为 usage 未知，保留已知累计数、登记 unknown/停止原因并阻断同任务后续工具轮次或重试。该策略覆盖 official/compatible 所有 provider：即使模型没有输出正文，已发请求也不能凭 SDK 默认零值证明未消耗 token；明确提供的非零用量按 SDK 报告的 total 与分项一致性核验后累计。

正式 AI contract 新增本地 127.0.0.1 HTTP SSE 服务，运行 Pi SDK 的真实 OpenAI-compatible adapter，不在 SDK 输出后改写消息：覆盖文本无 usage、工具调用无 usage 后的下一轮请求阻断、有效非零 usage chunk 累计、HTTP 错误无 usage 及同任务再次运行被阻止。独立探针 `npx tsx work/review-usage-http.ts` 与初始日志保持原样；复跑输出另存 `work/review-usage-http-fixed-20261028.log`，证实 `requests=1`、`requestCount=1`、`usedTokens=0`、`unknownRequestCount=1`、`status=unknown`。原脚本与日志 SHA-256 在复跑前后保持不变。
